# #19：压缩子树 DP 的操作计数与完整次数参照

日期：2026-11-13。冻结基线为 `b7ace6dcddedc6e46d12d9ce5d6e3609b665153f`。
本包测量子树精确判定器，暂不涉及 #23 的标准机器成本、见证回溯或统一时间上界。

## 三个执行版本

| 版本 | 保留状态 | 候选与合并 |
| --- | --- | --- |
| `checkCompact` | 活跃向量与线性费用 `(A,b)` | 上一包原执行器，源码保持不变。 |
| `checkFull` | 完整次数向量与线性费用 `(q,b)` | 相同列和枚举、支持包含条件、右折叠及线性费用算术；按完整 `(q,b)` 去重。 |
| `checkFast` | `(A,b)` | 仅在路线数 `m=1` 时直接生成唯一候选；其他路线数及全部合并／去重沿用基线。 |

完整次数参照使用 `(q,b)` 是为了统一两版的费用算术。
它与原 `(q,c)` 是可逆坐标变换：`c_i = b_i - parentCharge(v) q_i`，
`originalCost_roundtrip` 证明恢复 `b` 的等式。
完整次数状态不会按活跃集合提前合并；孩子表的投影保留重复项。
投影在局部候选循环之前计算，产生的支持向量与列表构造开销包含在耗时中。
因此该实验比较的是这两个明确的实现，不声称测出了与表示方式无关的压缩常数。

`computeFull_project_mem` 证明完整次数表投影后的成员集合与压缩表相同，
`checkFull_eq` 证明完整次数判定与已验证的原判定器相等。
这里不要求两个版本具有相同的表顺序或最终接受检查次数。

`compositionsFast_eq`、`computeFast_eq` 和 `checkFast_eq` 则证明优化版与基线
输出完全相等，包括表顺序。这个实验只检验候选生成特化，不能替代压缩／完整次数对照。
特化仅适用于全局路线数为一，不在多路线递归的最后一维偷偷引入额外优化。

## 计数口径与证明

统计器独立于计时运行。`DPStats.add` 对累计量求和，对最大列表长度取 `max`；
不把不同类别合成为所谓“总运行时间”。

| 字段 | 计入的高层操作 |
| --- | --- |
| `nodeCalls` | 进入非根子树递归的次数；根独立折叠不算一次子树调用。 |
| `compositionCalls`、`rangeChoices` | 列生成递归的调用次数，及每次尝试的首坐标值数量；包含最终没有输出的分支。 |
| `columnsGenerated`、`columnsAccepted` | 每个节点顶层列枚举输出数量，及通过根直接孩子次数上限的数量。 |
| `subsetCalls` | 每个候选下，对孩子表各元素调用一次完整支持包含判断。 |
| `insidePairs` | 通过支持检查后，实际进入向量费用加法的组合数量。 |
| `rootPairs`、`rootRejected` | 根的全部组合尝试，及随后因分配次数超过一而拒绝的数量。 |
| `ratAdds` | `addCost` 的逐坐标有理数加法：内部及根每个组合各 `m` 次；根被拒绝的组合也计入。 |
| `ratMuls` | 每个接受的局部候选，初始费用向量的 `m` 次有理数乘法。 |
| `dedupInput`、`dedupOutput` | 每次实际去重输入与输出长度之和；根输入指次数过滤后的列表。 |
| `eqCalls` | 去重时完整元素的相等判断次数，命中后短路；不把删除数量当比较次数。 |
| `acceptCalls` | 根状态上的完整接受谓词调用数，保留 `.any` 短路顺序。 |
| `maxRawTable` | 任一状态候选列表长度最大值，包括根次数过滤前的列表及折叠的单元素初始表。 |
| `maxDedupTable` | 任一次去重输出及折叠初始表的最大长度。 |

两项最大值不包含局部 `q` 候选列表或完整孩子表列表容器；列枚举另有数量指标。
它们不是峰值内存，多张表可能同时存活。
算术计数仅覆盖上表明确列出的向量运算，不计 `linearWeight` 系数构造、类型转换、
比较内部的坐标／位操作、支持向量构造、自然数运算或统计器自身开销。
一次有理运算或完整元素比较不是一个图灵机步骤。

`memberCounted_count` 使用独立短路扫描规格；`dedupCounted_count` 使用普通
`xs.dedup` 的尾表定义比较递推。`dedupComparisons_bound` 证明
`2 * comparisons ≤ n * (n - 1)`。全部不同时比较次数为 `n(n-1)/2`，
全部相同且非空时为 `n-1`；两种极端另有可手算回归。
理由是处理表头时，新增比较至多为去重尾表长度，进而至多为原尾表长度；
对长度归纳得到上界。元素互异时每层扫完整个尾表；元素全相同时非空去重尾表仅一项。
`dedupCounted_erase` 证明保留最右出现的列表顺序与固定版本 `.dedup` 完全一致。

内部单层计数规格为：支持检查 `|t|`，组合 `|filter(t)| |r|`，
费用加法 `m |filter(t)| |r|`。根单层组合及费用加法分别为 `|t| |r|` 和
`m |t| |r|`，费用先算，再做次数过滤。
`insideCostsStats_count`、`rootFoldStats_count`、`nodeTableStats_count`、
`computeCompactStats_count`、`checkCompactStats_count` 将统计结果连接到独立的规格递推；
规格使用原执行器的结果表，不依赖统计器输出。
`rootStep_conservation` 另外证明拒绝数与保留数之和等于组合数。
即使前面的孩子表为空，右折叠仍计算后面的表，没有加入空表提前退出。

所有统计版的擦除定理保留完整返回列表，包括顺序。
完整次数和优化版复用已证明的内部／根计数原语，并分别有整树结果擦除证明。
独立 Python 逐操作实现还逐实例核对三个版本的全部 17 个计数及有序表。

## 实验方法与结果

本轮 27 个实例全部完成，超时为零。三版全部 17 个计数、有序子树表及最终答案
通过独立 Python 实现核对；每个非根子树的状态集合及全树可行性另由矩阵枚举核对。

**压缩有实测收益，但不是普遍加速。** `zero_32` 中完整次数版 4.415 ms，
压缩版 1.558 ms，约快 2.83 倍；三路线零费用例约快 2.11 倍。
相反，`fees_8` 中压缩版 4.026 ms、完整次数版 3.394 ms，压缩版约慢 18.6%，
七轮配对测量中每轮都较慢。即使最大去重表从 65 降为 53、比较次数从 6,940 降为
6,238，也不能据此推断耗时下降。

下面是能区分原因的逻辑数量。`C/F` 表示压缩版／完整次数版，两个版本的列枚举数量相同。

| 实例 | 首坐标尝试 | 生成／接受列 | 支持检查 C/F | 内部组合 C/F | 去重比较 C/F | 最大去重表 C/F |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| zero_2 | 27 | 9/7 | 12/12 | 8/8 | 10/10 | 3/3 |
| zero_32 | 1197 | 69/67 | 102/1122 | 98/1058 | 130/2080 | 3/33 |
| fees_4 | 49 | 13/11 | 42/42 | 34/34 | 584/584 | 17/17 |
| fees_8 | 117 | 21/19 | 134/146 | 118/130 | 6238/6940 | 53/65 |
| three_routes_6 | 272 | 66/57 | 203/812 | 125/416 | 202/1143 | 7/28 |
| rational_short | 49 | 13/11 | 38/42 | 30/34 | 331/385 | 13/17 |
| rational_long | 49 | 13/11 | 38/42 | 30/34 | 331/385 | 13/17 |

`zero_32` 的列生成工作没有减少：仍有 1,197 次首坐标尝试，但支持检查、合并和去重比较
明显减少。`fees_4` 两版全部计数相同，压缩版中位耗时仍较长；`fees_8` 的计数也未能
预测耗时方向。完整状态可能更早通过次数向量判不相等，而压缩状态需要比较费用；
这是待验证的机制解释。本包没有测量比较内部的坐标扫描、单次原语耗时或分配成本，
所以不把去重比较数量直接转换为 CPU 时间占比。

`rational_short` 与 `rational_long` 是正比例缩放的费用／预算，三版各自的全部计数
都保持一致，但压缩版中位耗时分别为 458 µs 和 542 µs。数值位长以及运行环境波动
不会反映在这些高层计数中；这个小样本不能给出统一的位复杂度结论。

**单项优化的作用可独立观察。** `single_1024` 的枚举调用从 2,055 降至 3，
首坐标尝试从 2,052 降至 0；生成／接受列仍各 3 个，内部组合 2 个、根组合 1 个，
费用加法与乘法各 3 次，去重比较仍为 0。其余 15 个字段全部不变。
原版 882 µs，优化版 49.2 µs，约快 17.9 倍。
这定位了单路线大重数例的可避免枚举工作，而不是证明支持集压缩带来该收益。

这些是本轮观测范围，不是置信区间。实验规模固定为四顶点树、至多三条路线，
不能外推到大树、大路线数或其他运行后端。


固定 27 个实例定义在 [TreeBudgetSubtreeStatsBench.lean](../LeanCompletion/UAV/TreeBudgetSubtreeStatsBench.lean)。
包含路径重数、相同结构下的零／非零费用、多路线、根分支冲突、带符号费用、
不同位长的有理数、零路线。未预先把“预算降低”标记为不可行。
所有可行性答案及每个非根节点的两种状态集合均由独立矩阵枚举核对。

机器为 Intel Core i7-14650HX（16 核／24 逻辑处理器），Windows 11 10.0.26200；
Lean 为 `v4.30.0-rc2`，mathlib 固定于 `5450b53e5ddc75d46418fabb605edbf36bd0beb6`。
执行入口先导入已构建的 Lean 模块，再运行原执行器；构建、导入、输入输出和统计
均在内部计时区间之外。计时为当前 Lean `--run` 的编译模块执行环境，
没有把它描述为另行构建的本机 C 可执行文件性能。
每版先预热一次，之后每实例七轮、每轮二十次；每轮循环轮换三个版本的顺序。
报告每轮平均单次耗时的中位数。输入由 `IO.Ref` 读取，结果在结束时间戳前写回，
防止纯计算移出计时区间；循环、结果写回和校验和累加开销未扣除。
监督脚本对每阶段设 30 秒、每实例设 180 秒上限；超时单列，继续后续实例，绝不视为不可行。
