## 已证明的参数化结论

对同一个完整执行器 `executeStored`，`TreeBudgetStoredTotalWork` 已证明：

```text
work = steps + allocations
work <= 2^50 * S^3 * (ell+1)^7                  （解析和检查成功）
work <= 2^50 * 2^(3*M) * (ell+1)^7              （所有位串）
work <= 2^50 * (U+1)^(3*t) * (ell+1)^7          （所有位串）
```

`executeStored_work` 的数据前提是实际解析和检查成功的等式，不以容量界或总时间界为假设。
`executeStored_fpt_mass` 和 `executeStored_fpt_support_maximum` 代入
`S≤2^M` 与 `S≤(U+1)^t`；拒绝输入按参数零处理，其完整成本另有
`262144*(ell+1)^3` 界。因此两个参数化定理覆盖所有输入位串，多项式次数固定为七。
定理源与精确模型见 [TreeBudgetStoredTotalWork](../LeanCompletion/UAV/TreeBudgetStoredTotalWork.lean)
和 [A–E 状态记录](TREE_BUDGET_STORED_EXECUTION_STATUS.md)。

这里 `M,t,U` 由通过检查的输入重数向量经根坐标规范化后计算，分别为非根总重数、正坐标数和最大非根重数；不是未经规范化的输入字段或外层需求量。

这已经给出所选带地址位成本模型下的 FPT(`M`) 和 FPT(`t,U`)。
旧纸面目标 `O(S³(M+1)(ell+1)^5)` 与本次较宽松的已证界分开记录；
不能把旧纸面常数或次数移给新执行器。单独的事件计数、原语上界或假设总时间界的
代数引理仍不足以替代完整执行证明，而本包已补齐该前提。
若进一步声称标准图灵机分类，须另给模拟依据；这不是当前模型内的未完成证明。
参考模型的时间也不是 Lean 编译程序的实测时间。

一元编码的比较仍是纸面推论：若完整一元输入长度为 `N`，其到本二进制格式的转换
为多项式时间且输出位长 `ell=O(N)`，则由 `U≤N` 得到执行部分
`O((N+1)^(3*t+7))`，加上转换时间后仍是关于 `t` 的 XP 形式。
这里没有新增一元执行器的 Lean 定理。二进制编码没有 `U≤ell`，故不能沿用此推导。

## 显式输出的边界

取根和一个非根顶点的树，非根重数为 `m`、费用和预算为零。
每个合法单次根出发行必须使用该唯一边一次，成功矩阵恰有 `m` 行；
此时 `t=1`，输入重数仅需 `O(log(m+1))` 位，逐行序列化至少要写 `m` 个记录。
这是二进制输入下显式矩阵输出的长度障碍，不是否定判定问题属于 XP(`t`) 的证明。
它也没有给出仅树高、树宽或车辆数的分类。压缩矩阵、实际顶点路线展开和需求到 `H`
的包装器是另外的计算任务，不能从当前输出协议自动继承时间界。
