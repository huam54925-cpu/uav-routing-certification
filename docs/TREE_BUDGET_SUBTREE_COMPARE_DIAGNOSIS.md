## 待检验假设和干预边界

假设是：完整次数状态 `(q,b)` 可以因 `q` 不同而提前退出；压缩状态 `(A,b)`
更常进入费用比较，可能抵消减少状态和比较调用的收益。
这包含两个不同问题：比较路径是否改变，以及这种改变能否解释整程序耗时。
详细计数本身只能回答前者。

先按 `inside`、`node`、`root` 标记原派生比较器的去重调用，再只对节点最终去重
加入显式比较策略。内部费用折叠和根折叠继续用冻结版本的相等判断。

| 计时版本 | 状态及节点比较策略 |
| --- | --- |
| `C_original` / `F_original` | 上一包原压缩／完整次数执行器，作独立参照。 |
| `C_K` / `F_K` | 显式先比较支持／次数向量，相同才比较费用向量。 |
| `C_B` / `F_B` | 显式先比较费用向量，相同才比较支持／次数向量。 |

唯一干预是节点比较器的字段顺序。显式向量比较按坐标 `0,…,m-1` 扫描，遇到第一个
不同坐标就停止。纯计时版本用 `List.finRange` 与 `List.all`；诊断扫描另返回坐标检查数。
四个干预版本共用这套扫描和同一个右向去重实现，均保留最右出现的状态。
内部费用去重、根去重、候选枚举、孩子表缓存和预算条件均保持。

显式扫描不冒充原派生数组相等的执行过程。它可能引入索引列表、函数包装及编译差异；
所以原始版本与显式版本之间的时间差不能全归因于字段顺序。
固定工具链中，`Vector` 派生相等依赖数组相等，数组实例有编译期替换；
`Rat` 保存已规范化的分子／分母并派生 `DecidableEq`。
一次 `Rat` 相等判断不是交叉相乘，也不是重新约分。
这些事实来自本地固定源码，对应
[Vector/Basic](https://github.com/leanprover/lean4/blob/v4.30.0-rc2/src/Init/Data/Vector/Basic.lean)、
[Array/DecidableEq](https://github.com/leanprover/lean4/blob/v4.30.0-rc2/src/Init/Data/Array/DecidableEq.lean)、
[Rat/Basic](https://github.com/leanprover/lean4/blob/v4.30.0-rc2/src/Init/Data/Rat/Basic.lean)。

## 记录与形式化接口

每个去重调用记录节点、阶段、孩子位置、输入／输出长度及比较调用数。
内部／根右折叠的位置按原孩子列表从零编号，记录顺序仍是先尾部再当前孩子；
节点最终去重的位置字段固定为零。
不保存候选矩阵、比较对象或状态对列表。

节点详细记录增加：`keyVectorCalls`、`keyRejects`、`costVectorCalls`、`costRejects`、
`equalStates`、`keyCoordinateChecks`、`ratCoordinateChecks`。
其中一次有理坐标检查计一次完整 `Rat` 相等判断，不计分子／分母或位操作。
`detailAvailable=false` 的行只测完整元素调用；其详细字段的零值表示未插桩，
不能解释为没有发生费用比较。

先键比较满足 `calls = keyRejects + costVectorCalls`，
`costVectorCalls = costRejects + equalStates`。
费用优先则满足 `calls = costRejects + keyVectorCalls`，
`keyVectorCalls = keyRejects + equalStates`。
这些守恒关系在 Lean 中逐次证明，并在实际节点累计记录上核对。

证明分层如下：

- `scan_spec`、`vectorScan_count`：布尔结果及独立短路扫描计数规格。
- `compactEqDetailed_correct`、`fullEqDetailed_correct`：显式比较与状态相等一致。
- `dedupWith_correct`、`dedupDetailed_spec`：去重列表及顺序不变，完整元素调用数恢复旧递推。
- `dedupDiagnostic_collapse` 与 `dedupDiagnostic_rows`：单次记录对应实际去重，恢复旧统计。
- `checkCompactDiagnostic_collapse`、`checkFullDiagnostic_collapse`：整个诊断返回的 `Measured`
  与上一包完全相等，同时恢复判定结果及全部 17 项统计，累计量与最大值按旧规则汇总。
- `computeCompactOrder_eq`、`computeFullOrder_eq`：每个子树有序表保持；
  `checkCompactOrder_eq`、`checkFullOrder_eq`：四个干预执行器的最终判定保持。

没有更改已有 `CompactRep`、`MatrixFeasible` 或其精化定理。

## 同一份状态对上的数学解释

令 `L(b,b')` 是显式费用向量扫描检查的有理坐标数。
`keyFirst_ratWork` 将详细计数连接到这个独立规格；`projection_pair` 与
`projection_pairs` 证明，对固定完整状态对列表 `P`：

\[
R_C(P)=R_F(P)+\sum_{((q,b),(q',b'))\in P}
  \mathbf 1[q\ne q'\land\operatorname{supp}(q)=\operatorname{supp}(q')]L(b,b').
\]

证明逐对分为三种情况：次数相同则支持相同，两版都比较费用；次数不同但支持相同，
只有压缩比较进入费用；支持不同则两版都提前退出。对列表求和即可。
这里两边必须使用**同一份状态对列表**。实际两版的表、去重及比较序列不同，
所以这不是实际压缩运行费用检查数总不小于完整运行的定理。

## 本轮观测

六个实例全部完成，无超时。每条阶段记录、详细计数、全部 17 项旧统计、
有序状态表和独立矩阵枚举全部一致。

**比较路径差异得到确认，但“费用比较更多，所以原压缩版更慢”不是充分解释。**
`fees_8` 的键优先模型中，完整次数版检查 1,630 个有理坐标，压缩版检查 3,124 个，
约为 1.92 倍；压缩版也检查了更多键坐标。
然而费用优先使两种显式版本都加快，即使有理坐标检查进一步增加。
本包因此收获的是部分机制解释与一个有条件的干预结果，没有找到原始时间差的唯一原因。

### 一项干预：费用字段优先

| 实例／版本 | 键坐标检查 | Rat 坐标检查 | 节点完整比较 |
| --- | ---: | ---: | ---: |
| fees_4/C_K | 544 | 244 | 282 |
| fees_4/C_B | 0 | 282 | 282 |
| fees_4/F_K | 448 | 166 | 282 |
| fees_4/F_B | 0 | 282 | 282 |
| fees_8/C_K | 6400 | 3124 | 3230 |
| fees_8/C_B | 24 | 3242 | 3230 |
| fees_8/F_K | 5124 | 1630 | 3494 |
| fees_8/F_B | 12 | 3506 | 3494 |

`fees_8` 的 `C_B` 跳过了几乎全部支持扫描：键坐标由 6,400 降为 24，
Rat 坐标则由 3,124 增至 3,242；`C_K/C_B` 的配对比值中位数为 **1.404**。
完整次数版也从键坐标 5,124 降至 12，Rat 坐标由 1,630 增至 3,506；
`F_B/F_K` 的配对比值中位数为 **0.806**，即费用优先反而约快 19.4%。
这没有支持“让完整版更常比较费用会明显变慢”的预测。

费用向量在这些非零费用例中很有区分力，通常首个坐标就拒绝。
数据支持把字段进入次数、键扫描与费用扫描一起考虑；不能只用 Rat 坐标数量解释时间。
零费用例中费用不能提前排除状态，费用优先没有给压缩版带来稳定收益，
并使 `zero_8` 的完整次数显式版配对中位耗时增加约 9.0%。

**该干预没有替换默认执行器。** `fees_8` 的 `C_B` 中位耗时 4.518 ms，
原压缩版为 3.874 ms；显式扫描有明显额外成本。
`C_K` 相对原压缩版的配对比值中位数为 1.669，`F_K` 相对原完整版为 1.761。
因此 1.404 倍是相同显式扫描实现内的顺序收益，不能宣传成原 DP 加速 1.404 倍。

### 剩余解释空间

本轮另检查了生成的两个派生相等函数定义：它们确实先检查 `active`／`q`，
相同后检查 `cost`。这支持字段入口这一层的解释；数组内部如何扫描、共享对象如何
处理，仍不能由显式坐标计数推断。

对源码等价的显式向量比较、原比较包装、两个节点函数做了小范围
`trace.compiler.ir.result` 检查。显式向量探针的 IR 出现谓词闭包 `pap`、
`List.finRange`、`List.all`、数组取值和 `inc`／`dec`；原比较包装调用已有派生相等函数。
两个节点探针继续调用原来的专门化辅助函数，完整次数版还出现孩子表投影的 `map`。
这证明生成路径确有差别，提供了显式版本额外开销的候选来源，
没有量化各项分配、共享、引用计数或比较内部的时间占比。

例如 `fees_8` 节点的键优先显式向量入口总数，C 为 `3230+3112=6342`，
F 为 `3494+1630=5124`；费用优先后分别为 `3230+12=3242` 与 `3494+12=3506`。
它同时减少了键扫描和向量入口的固定开销，因此本次干预不能把这两项的耗时贡献分开。
当前结论是**比较路径解释了一部分行为，实际原版差距仍有未分解的运行时因素**。
后续若继续优化，应优先保留原数组比较实现再单独测试字段顺序，避免把显式索引列表的
开销一并带入；本包没有额外加入这一第二项干预。

显式扫描的 IR 核查可将以下探针放在本地忽略目录，用 `lake env lean` 运行并保存输出：

```lean
import LeanCompletion.UAV.TreeBudgetSubtreeComparePrimitives
open UAVProof.TreeBudgetSubtreeExecutable
set_option trace.compiler.ir.result true in
def compareScanProbe {m : Nat} {α : Type} [DecidableEq α]
    (x y : Vector α m) : Bool :=
  (List.finRange m).all fun i => decide (val x i = val y i)
```

这些检查在正式计时结束后运行；未把探针编译时间或其输出混入基准结果。


## 测量方法与复现

六个实例直接筛选上一包冻结的实例列表。先运行独立诊断，再预热六个未插桩计时版本。
每次校准让六个版本用相同重复次数，逐次加倍，直到最短批次约达到 100 ms，
或达到 4,096 次的上限。校准会产生额外预热；正式测量仍只取后面的七轮。
每轮循环轮换六个版本的顺序，输入由 `IO.Ref` 读取，结果在结束时间戳前写回。
循环、结果写回和校验和开销未扣除；不对每次状态比较读取时钟。
构建、导入、统计和输出均不进入计时区间。阶段上限 60 秒、实例上限 300 秒；
超时单独记录并继续下一实例，不视为不可行。

时间报告区分“每轮配对比值的中位数”与“两组中位耗时的比值”。
它们一般不相等；前者作为本包干预对照的主要比值。
没有把操作数量相加当作时间，也没有将某类调用数转换为耗时百分比。
