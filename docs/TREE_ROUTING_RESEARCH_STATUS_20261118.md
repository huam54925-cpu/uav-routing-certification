# 精确树路由：当前成果、证据边界与研究定位

日期：2026-11-18。研究分支：`research/structural-service-cuts-20261023`。本次阅读的证明基线为 [`f3ea0823be69ffa7152dec903069c2ba79ad20a4`](https://github.com/huam54925-cpu/uav-routing-certification/commit/f3ea0823be69ffa7152dec903069c2ba79ad20a4)。

本页是当前导航与研究定位说明。它不替换各证明包的历史验收记录，不构成新的 Lean 构建、公理审计、Python 实验或 LaTeX 编译。本文档批次不修改证明源、依赖锁、数据、默认求解器或历史应用材料。

## 1. 当前研究对象

给定带根树、非根父边的精确双向重数 `H`、恰好 `m` 条路线、有理服务费用 `s` 和逐路线预算 `T`，研究是否存在合法 depot 路线实现该边流，并进一步求最小可行预算及其证书。路线内部不经过 depot，相邻顶点不同，允许重复访问；每次访问都计数并计费。树矩阵层允许有符号费用与预算。

每条路线以父边重数行 `p` 表示。核心条件为列和、每行一次基地出发、祖先正支持封闭、逐行线性费用。祖先封闭不是错误的 `p_child ≤ p_parent`。子边可以多次往返，父边仅进入一次。

仓库源于 UAV 算例，但当前每次访问计数的数学模型与原算例中同一无人机重复到访不重复计覆盖的语义不能默认等同。现有线性旅行费用编码覆盖树边上的有理加性方向费用，不覆盖时间窗、等待、顺序相关能耗或连续轨迹。更一般图的访问副本/next 证书是另外一层，不能把树求解器推广到一般图。

## 3. 对常见评价的修正

| 容易混淆的表述 | 本项目采用的准确表述 |
| --- | --- |
| “完整证书证明了这个预算最优。” | 原检查器检查可行性。最优性来自求解器及 `optimize_spec` 的通用正确性证明；一般独立短最优/不可行证书没有由此得到。 |
| “已经证明 FPT，所以实际求解一定快。” | #22 的 FPT 属于已明确的执行/位成本模型，参数依赖和常数可能很大。实际性能需要同任务、同输出契约的测量。 |
| “旧缓存小例慢三倍，说明现在所有算法没有竞争力。” | 原关联列表执行器上的小例不能外推到后来的子树 DP 或未来置换商算法；目前也不能反向声称它们更快。 |
| “没有冷构建，已有证明就是无效的。” | 已记录定向构建和公理审计是相应范围的证据。独立全量复现是另一项交付，二者不能互相替代。 |
| “直接 lake build 就等于全部研究模块验收。” | 必须核对实际根导入、目标和审计清单。现有各包提供显式目标；不能用未覆盖研究模块的默认目标冒充全量验证。 |
| “#19 完全没有地址/分配结果。” | 已有去重堆表示和局部收费模块；缺的是所有 DP 阶段的统一完整执行连接。 |
| “逐顶点路线输出还没有实现。” | 指定的树证书到路线构造、规范投影与长度已完成；更一般见证转换及输出成本仍须独立描述。 |
| “树宽小，所以容量/预算问题应当容易。” | 现有严格 hub 困难性已发生在高度二树；树宽、重数、路线数、费用类型不能混为一个参数。 |
| “有符号费用导致所有摘要压缩都失效。” | 某些剪枝需要符号假设；新接口反例甚至可在非负费用下成立。失败原因须由具体反例定位。 |
| “用了整数锥、对称性或代表集就是原创算法。” | 这些方法有明确文献来源。候选贡献是本模型的精确编码、结构界、接口下界、正确合并与可检查证书连接。 |
| “现有成果保证某类期刊/会议录用。” | 研究主题与形式化、认证优化相符；新颖性、论证、复现、写作与审稿结论仍须独立判断。 |

## 4. 新研究的证据分层

本轮文献与推导详见 [2026-11-18 文献检索](TREE_BUDGET_LITERATURE_REVIEW_20261118.md)，实施详见 [三项研究计划](TREE_BUDGET_INNOVATION_ROADMAP_20261118.md)。

下一阶段分别由 [#24 稀疏证书](https://github.com/huam54925-cpu/uav-routing-certification/issues/24)、[#25 指定补全接口](https://github.com/huam54925-cpu/uav-routing-certification/issues/25)、[#26 路线置换商 DP](https://github.com/huam54925-cpu/uav-routing-certification/issues/26) 追踪；#15/#19/#21/#22/#23 保留当前分工与历史验收记录。

1. **A：稀疏证书。** 单行多面体线性化、整数锥等价、子集和与奇偶中点的两种支持界已有纸面推导；Lean 形式化、二进制证书编码及检查器位时间待实施。它可以改变一份解的模式重数/模式内容，不应冒称仅做稳定去重。
2. **B：接口边界。** 五顶点树上指定补全的单位兼容矩阵已有纸面推导；一般等价类计数、树实例及置换版的 Lean 验证待实施。指数等价类数不等于任意摘要都需要指数位数，更不是所有求解器的时间/空间下界。
3. **C：置换商 DP。** 运输表与相对匹配的完整性、联合类型和见证恢复构成设计依据；商执行器、整个 DP 归纳、计数与比较均待实施。不得以各子状态独立排序后同序相加代替匹配。

外部整数锥结果支持按维数的 XP 推论，并有 2026 年预印本给出更强的构造性 FPT 依据。本文档把它们作为外部定理的模型应用，不把外部算法添加为 Lean 公理，也不把这些结果写成当前仓库已验证的 FPT(n)。外部 ETH 下界的转移同样需要保留归约、参数和来源假设。

## 5. 输出与契约选择

旧执行器保持整份 `Option Certificate`、原顺序与 tie-breaking 的定理继续有效。新算法的第一契约是可行性和最优预算等价，并输出原检查器接受的完整证书。新稀疏化可以改变路线模式；即便总边流、路线数、预算和最优值不变，也不能把结果称为与旧矩阵逐字相同。若另要求相同旧证书，需要额外的来源顺序信息和证明，不作为 A/B/C 的默认验收条件。

显式路线输出与压缩证书输出分别计费。二进制重数可以很大，`2M+m` 是已证列表大小，不会因存在短模式证书而缩小。短证书存在不推出多项式求解，不推出全部预算断点可短时间物化，也不推出不可行性具有同样短的证据。

## 6. 当前投入次序

优先完成 A 的行多面体与支持界，同时完成 B 的反例族；在联合类型和匹配契约固定后推进 C。#19 剩余执行计费作为独立收尾，不让它阻塞新结构理论，也不把未完成范围隐藏。#22 保留最终验收，#23 旧归约机器成本保持独立，#21 承接表示和见证恢复。
