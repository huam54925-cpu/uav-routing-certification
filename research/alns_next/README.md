# 固定机队 ALNS 后续研究原型

针对论文问题一的后续改进：以 Case1 固定三架突破 10.3195 小时为主要研究目标，最终仍按每条路线不超过 9 小时验收。

实现四类破坏、贪心/regret-2 修复、自适应算子权重，以及 2-opt、2-opt* 和长度 2～3 的 Or-opt。分别保存最好最长时间、最低总超时量及九小时内可行解。独立验证器从坐标重算距离、时间与任务覆盖。

## 运行

### Linux 远端持续运行（2026-10-15 加固）

不要直接把单次 `alns_solver.py --seconds ...` 当作无人值守守护程序。
在本目录使用新入口，默认持续运行；每六小时生成快照，然后继续搜索：

```bash
mkdir -p runs/case1_n3
nohup python3 -u run_remote.py --case Case1 --fleet 3 --workers 8 \
  --slice-seconds 600 --output runs/case1_n3 --port 8765 \
  > runs/case1_n3/console.log 2>&1 < /dev/null &
```

首次启动一分钟内查看 `runs/case1_n3/progress.json`：应有活动进程、非空最好档案和刷新的检查点。
`--warm review_smoke.json` 可接本次短测的三架最好档案；不要传四架方案或物理点编号格式。
输入、机队规模不符会在启动阶段拒绝。已有同目录任务运行时会拒绝第二个守护进程。

`run_remote.py` 每个工作进程运行一个十分钟片段，然后从全局精英档案继续。
一半进程偏重最长时间，一半偏重总超时量；片段重新升温、换种子和恢复算子权重。
不是随机数状态的精确恢复，也不是完整遗传岛模型。
子进程报错会退避重启；超过片段时限60秒先请求保存退出，再过10秒仍无响应则杀掉并重启。
检查点每约10秒、每次档案改善以及正常停止时原子写入并 fsync。
初始化完成后立即保存初解；初始化未成功时会记录错误并换种子重试。

本地通过 SSH 转发查看进度：

```bash
ssh -N -L 8765:127.0.0.1:8765 用户名@服务器地址
```

浏览器打开 `http://127.0.0.1:8765`。HTTP仅监听服务器本机；关闭查看连接不停止搜索。
需要自定义SSH端口时在ssh命令加入 `-p 端口`。

输出：

- `best.json`：经独立复算的全局三类档案，可继续热启动。
- `best_physical.json`：物理点ID路线，便于查看；不要作为内部任务副本热启动输入。
- `worker_XX.json.checkpoint.json`：单进程检查点。
- `progress.json`：最好时间、超时量、活动进程、PID、重启/错误及检查点年龄。
- `snapshot_.../`：每六小时的阶段文件；不中止搜索。

停止：`touch runs/case1_n3/STOP`，等待 `progress.json` 显示 `stopped`。
恢复前删除STOP，使用相同目录执行同一启动命令。已保存三类档案不会因重新开始而丢失。
`--run-seconds 60` 仅供短测；默认0不自动停止。`--port 0` 可关闭HTTP。

本程序不会关机。nohup防SSH断线；不保证主机重启、磁盘满、父进程被杀、云平台回收或余额耗尽后仍能运行。
主机故障后需重新启动入口；子进程最多继续至当前片段结束。不要在旧子进程仍写文件时手工启动另一份。
不承诺六小时必定找到九小时可行解；仍只能输出FEASIBLE或UNKNOWN。

### 守护与恢复测试

```bash
python3 -m unittest -v test_solver.py test_remote.py
python3 validate.py runs/case1_n3/best.json
```

新增实际子进程测试覆盖：杀掉工作进程后的自动重启、重复启动拦截、信号停止后保存、重启后不退化、阶段快照及HTTP读取。
这类短测验证运行机制，不代表六小时稳定性或解质量证明。

本次另做两进程16秒短测及从其档案继续45秒的运行测试，最好三架路线为
`10.2402003894 / 10.2686495865 / 10.2532593901` 小时；独立复算通过。
`review_smoke.json` 保存此热启动见证，`remote_validation.json` 保存输入核对和复算记录，
`remote_test_results.txt` 保存7项测试结果。仍为UNKNOWN，未达到九小时；
与论文旧六小时运行不构成公平性能对照。

仅需 Python 3 标准库。在本目录执行：

```bash
python3 alns_solver.py --case Case1 --fleet 3 --seconds 60 --seed 0 --out case1.json
python3 validate.py case1.json
python3 -m unittest -v test_solver.py
```

使用 `--focus violation` 增强超时惩罚，使用 `--warm case1.json` 从此前最好时间路线重新开始。检查点支持热启动，尚不支持随机数与退火状态的精确恢复。
