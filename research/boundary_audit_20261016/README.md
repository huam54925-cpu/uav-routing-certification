# 下界核查与六小时路线诊断（2026-10-16）

本次没有启动优化长跑。使用原题模型：每次巡检服务5分钟，等级访问次数3/2/1；允许同机 A→B→A，不允许把同点连续停留算两次；两架各访问一次算两次；基地(0,0)，单位0.1 km、速度55 km/h、单机上限9小时，无中途回库。核对附件1.xlsx与instances.json，四个算例的坐标、点编号和访问次数一致。

## 1. 审计结论与修复

`program/run.py::strong_lower_bound` 原先使用“每次访问到两个不同邻居的最短距离之和再除以2”的度下界。这不适用于本题，已替换为允许重复邻居的有效下界。搜索算法与既有解未改动。

反例（原坐标单位）：基地D=(0,0)，A=(100,0)，B=(101,0)，A、B各需3次访问。合法路线为 D→A→B→A→B→A→B→D，飞行距离20.6 km，服务0.5 h，实际总时间0.874545455 h。旧度公式给出30.45 km、1.053636364 h，甚至会错误排除1小时内可行的这条路线。

令 r_i 为访问次数，m_i=min_{j≠i} d_ij（包括基地），m_0=min_i d_0i。对恰好N条非空路线，正确度下界为：

L_deg(N) = Σ_i r_i m_i + N m_0。

证明：每次任务访问的两条关联边各至少m_i，允许前后邻居相同；基地有2N条关联边。对所有关联边求和再除以2。另有MST下界：所有路线边并集连接基地及每个物理点。

循环覆盖下界L_CC(N)：构造M个任务副本和N个基地副本，每个副本一入一出；禁止同物理点副本相连及基地副本互连。每组合法实际路线都可映射成一个可行指派，所以最小费用指派值不超过实际总距离。它允许无基地子环、一个环含多个基地副本，也不限制每机9小时，因此仅是松弛。

取 L(N)=max(MST,L_deg(N),L_CC(N))，则：

Tmax ≥ max{(M/12+L(N)/55)/N, max_i(2d_0i/55+1/12)}。

代码将欧氏距离保守向下取整到10^-6 km；用整数匈牙利算法求指派，并验证完整原始/对偶证书（所有对偶约束、排列、原始与对偶目标一致）。比较9小时使用有理数，避免把浮点微差当作严格证明。证书证明的是松弛子问题费用，不是原路由问题的全局最优。

## 3. 已有路线的定点诊断

只分析两个六小时快照中的best_makespan档案，不把best_violation档案的V拼接到这些路线。输入ZIP的SHA256保存在route_diagnostics.json。恢复后重新检查任务完整性、相邻访问规则、实例指纹、机队数量与时间；代表性修改另经独立validate.py复核。

### Case1：往返与共享边

- UAV1的51→11→51飞行57.008771 km；UAV2的4→43→4为49.040799 km。中间点也完成必要任务，不能把这些距离全部称为浪费。
- 最长连接包括UAV3的29→基地68.410526 km；基地↔21的55.337600 km边由UAV1和UAV2各用一次。
- 试把UAV2的片段6→4→43中的一次点4访问，转移到UAV1的43→15之间：源路线少5.479787 km，目标路线多10.346119 km，总距离反而增加4.866332 km；Tmax变为10.504682455 h。这是受测单点转移中Tmax最低者，仍比原解差。

### Case3：省距离不等于降低最长时间

- 长连接包括UAV2的基地→52（55.142616 km）、11→基地（43.345305 km），以及UAV3的40→52（36.322462 km）。基地边有往返要求，不能直接删除。
- UAV2与UAV4共享无向边11—36（16.939996 km）、36—57（10.049541 km）、47—57（10.044984 km）。这提示应检查这些区域的任务划分，但重复访问需求也可能合理地产生共享。
- 将UAV3的3→10→33中一次点10访问转给UAV2，插入27→79之间：源路线少5.677016 km，目标多5.048345 km，净节省0.628671 km。目标无人机还需接收5分钟服务，工作时间增加10.507286分钟；全局Tmax反而变为9.533137492 h。
- 另一转移：将UAV1的41→43→基地中的点43交给UAV2，插入11→基地之间。总距离增加0.425055 km，Tmax变为9.450656488 h；这是该限定单点转移邻域的最好Tmax，也未改善。
- 同一点两次访问间的长闭合片段可能包含几十次必要任务。例如UAV1两次点43访问之间有38次中间访问，316.0548 km不是可直接删除的冗余绕行。

### 完整枚举的限定邻域

| 算例 | 合法单点跨机转移 | 降低Tmax的转移 | 节省总距离的转移 | 合法一对一交换 | 降低Tmax的交换 |
|---|---:|---:|---:|---:|---:|
| Case1 | 522 | 0 | 0 | 699 | 0 |
| Case3 | 4388 | 0 | 2 | 4008 | 0 |

范围：转移只从同机已重复访问的点取一个任务副本，交给尚未访问该点的另一架，枚举所有插入位置；交换至少有一个被交换点在原机上重复访问。其他顺序不动；删除接缝与插入接缝必须合法。计数按带标签的任务副本候选计，可能有物理等价候选。严格改善阈值1e-10 h。共享统计仅指完全相同端点的无向边，不涵盖几何线段部分重叠或交叉。这些结果不能推广成“所有跨机重排无效”或完整邻域局部最优证明。

## 4. 下一步的具体对象

1. **优先补强下界的连通性。** Case1 N=3的指派解有22个环，其中20个不含基地；Case3 N=4有51个环，其中48个不含基地。这解释了当前下界偏松。下一小实验可以加入任务子集到外部的连通割，再求LP下界并报告界提升；只有经验证的下界超过9小时才可能排除对应N。有限路线池不可行不构成原问题不可行证明。
2. **路线改进先做带负载补偿的成组重排。** 以Case3的11—36—57—47共享区域、点10转移为对象，把转移与另一方向任务回填联合优化，服务次数和路线负载必须一起计算。先测少量固定窗口与明确片段，记录距离、服务时间、Tmax及独立合法性。当前没有证据承诺成组操作能改进。
3. **主问题约束保持不变。** 放宽时间上限可作为后续敏感性分析，但不能代替9小时下Nmin的回答。也不建议在完成上述定点验证前再购买六小时重复搜索预算。
